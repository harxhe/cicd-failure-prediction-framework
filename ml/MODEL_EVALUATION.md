# M2 Model Evaluation

## Evaluation Scope

The saved local XGBoost artifact was evaluated against the chronological Day 6
holdout dataset:

- Model: `xgboost-model`
- Evaluation data: `day6-test.csv`
- Rows: `576,257`
- Input format: headerless CSV, label in column 0
- Decision threshold: `0.5`
- Features: the deployed six-feature model contract

The test labels contain 430,624 successful builds and 145,633 failed builds.

## Results

| Metric | Result |
|---|---:|
| Accuracy | 0.822548 |
| Precision | 0.715734 |
| Recall | 0.494064 |
| F1 | 0.584591 |
| ROC-AUC | 0.827355 |

### Confusion Matrix

Rows are actual labels and columns are predicted labels, using the order
`[[true negative, false positive], [false negative, true positive]]`:

```text
[[402047, 28577],
 [ 73681, 71952]]
```

The model identifies approximately 49.4% of failed builds at the 0.5 decision
threshold. Recall is the main tradeoff to review before treating the model as a
high-sensitivity alerting system.

## Reproduction Notes

The model is a legacy binary XGBoost artifact. The evaluation used the original
XGBoost 1.3.3 reader with temporary NumPy compatibility aliases because the
current NumPy release removed APIs expected by that reader. No model, dataset,
or project dependency was modified.

The deployed endpoint remains the source of truth for live inference. This
report documents local holdout evaluation only; it does not claim that these
metrics were generated by SageMaker.

## Limitations

- `test_coverage_delta` and `author_recent_failure_rate` are unavailable and
  are not part of the deployed six-feature model.
- Integer encoding is used for the categorical time and weekday features.
- Threshold selection was fixed at 0.5 for this report; changing alert
  sensitivity requires team review.
